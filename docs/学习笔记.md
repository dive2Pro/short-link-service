## 第二章

- Record 的另外一种创建方式: public record CreateLinkRequest(String: code){};
- dto 是 Data Transform Object 的缩写. 用于定义数据在业务中交互的结构
- @RequestBody 是 Sprint Boot 中用于获取请求中的 body, 并将其转化为传入的 record 结构

  @PostMapping("/api/links/{code}")
  public String create(
      @PathVariable String code,
      @RequestParam String source,
      @RequestBody CreateShortLinkRequest request
  ) {
      // POST /api/links/hello?source=web
      // code = "hello"
      // source = "web"
      // request 来自 JSON 请求体
      return request.originalUrl();
  }

## 第十章

- 数据库短暂故障时, 可能是和扩容, 网络抖动, 或者其他的可复原的, 独立, 临时的错误相关. 不重启所有实例, 是因为这样做并不一定就能解决问题, 二是没有必要, 局部问题不需要也不应该视作整体性的结构问题. 
- 服务不可用. 不代表用户体验. 服务不可用, 又不能及时正确的通知用户才是用户体验问题. 
- actuator 是 Sprint Boot 的一个插件.
- actuator 检测: liveness, readness, metrics
  - liveness 代表服务是否还在运行, 没有崩溃或卡死
  - readness 代表是否准备好接受流量. 数据库出错, 缓存等子模块出现问题, status 是 "DOWN"
  - metrics 记录的是系统的设置的方方面面, 比如吞吐量, 正常通过量, 错误率等
- 负载均衡根据 actuator 的状态, 动态分配流量
- 为什么要多个只读副本数据库.
  - 根据服务的场景来规划的. 当前服务的业务属性规定了流量是写少读多
  - 隔离读写压力. 多个只读副本可以降低主写数据库的负载, 提高写入的效率
  - 只读副本可以充当容灾备份
